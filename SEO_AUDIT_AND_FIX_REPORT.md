## Priorities and observed baseline

The live audit checked 108 HTTP page URLs (107 returned 200; one deliberately nonexistent control returned 404), seven paired desktop/mobile pages plus targeted mobile checks, and inventoried 6,533 unique URLs across five sitemaps. It did not fetch every sitemap page. All 60 distinct homepage targets and 11 active catalog destinations returned 200.

1. **P1 — inventory integrity:** `/imoveis.html` showed 11 active properties but its ItemList referenced five different, older property URLs.
2. **P1 — older mobile templates:** an 800px image expanded three checked 390px mobile layouts to an 816px document width.
3. **P1 — indexation:** prospecting/operational pages were explicitly indexable and in sitemaps. Public intelligence documents must not be indiscriminately blocked with all `/docs/` content.
4. **P2 — metadata:** 38 of 107 successful HTML URL variants lacked OG images; 46 lacked explicit Twitter cards. Some descriptions said only `Voltar para a Praia Digital`.
5. **P2 — technical quality:** broken skip-link targets, a schema logo 404, analytics placeholders and oversized gallery images need attention. All 18 missing alt attributes found in raw HTML were tracking pixels, not property photographs.

The current homepage already had a relevant title and description, a self-canonical, complete social cards, valid JSON syntax in its JSON-LD and working responsive navigation. No Lighthouse/CrUX score, ranking lift or full accessibility certification is claimed.

## Implemented source/build fixes

- `scripts/seo_audit.py` reads the **existing authoritative `const properties` dataset in `js/main.js`**. It refuses to invent inventory if that dataset is missing or malformed. Static ItemList, initial crawlable cards and current-inventory sitemap entries are generated from the same data and ordering used by the catalog.
- `js/catalog-seo.js` updates that ItemList when the visible catalog is filtered, including an empty-result list. It does not invent prices, ratings or offers.
- `css/seo-responsive.css` constrains picture/main/hero images with `max-width: 100%; height: auto`. It does not conceal document overflow with `overflow-x: hidden`.
- The static build pass injects that CSS into every processed HTML head, writes one production canonical per page, reconciles OG/Twitter title/description/URL/image tags, repairs the known schema-logo path and collapses duplicate controlled metadata.
- Canonicals use each page's **own URL under `https://praia.digital/`**, not the fork's hostname or the homepage for every page. Directory index files consolidate to directory URLs. Existing genuine local canonical aliases are retained and noindexed rather than made into competing pages.
- Explicit existing noindex/nofollow decisions are preserved. Known operational filenames, operational directories, thank-you pages, dashboards and internal sales/product/SEO documents receive server-readable noindex tags in the generated HTML. Useful `docs/inteligencia/` content is not blanket-excluded.
- `robots.txt` permits rendering assets and allows public noindex pages to be crawled so their directives can be read. It is explicitly not presented as access control.
- All existing root `sitemap*.xml` files are parsed and regenerated by the build pass: only locally existing HTML, intended-indexable pages and their production canonical URLs are included. Redirect/meta-refresh, noindex, internal, missing and canonical-alias targets are excluded; URLs are deduplicated. The main sitemap retains the union of eligible existing sitemap candidates plus active listings. No unverified lastmod dates or priority claims are manufactured.
- The existing deployment preparation sequence invokes the pass **after listing retirement enforcement and before the existing sitemap validator**. A repository/branch guard prevents the deployment job from running in this fork even if someone later enables Actions.

### Important generated-file distinction

Bulk HTML head changes and regenerated sitemap XML are **build outputs**, not thousands of separately committed page rewrites. The source XML snapshot is not claimed to have been exhaustively cleaned merely by committing this generator. To inspect the prepared static artifact locally, run:

```sh
python3 -m unittest discover -s tests -p 'test_seo_audit.py' -v
python3 scripts/seo_audit.py --root . --apply
python3 scripts/seo_audit.py --root . --check
python3 scripts/validate_sitemap_targets.py
```

The build pass is wired into the existing upstream preparation workflow but **no workflow was enabled or dispatched**. No change is live at praia.digital. This distinction is intentional: all changes remain reviewable source on a non-deploying branch.
